# Wally 테스트 체크리스트 결과

- 기준 문서: `docs/ref/3_test_checklist.md`, `docs/ref/2_test_scenarios.md`
- 작성일: 2026-08-10
- 확인 기준: 현재 소스, 기존 Android 실기기·WebView 검증 기록, `npm run build` 성공

## 판정 표기

- `[x]` 구현 및 기존 검증 기록이 있는 항목
- `[-]` 일부 구현되었거나 실제 Babycat 연동 재검증이 필요한 항목
- `[ ]` 미구현 또는 이 환경에서 실행하지 못한 항목

> 실제 Babycat 백엔드, RTSP 카메라, 초기 계정이 필요한 절차는 이번 환경에서 실행하지 않았다. 해당 항목은 체크하지 않고 결함 기록 또는 비고에 남겼다.

## 0. 사전 준비

- [ ] Jetson 실기에 babycat 저장소를 배치하고 `.env`(`HOST_IP`·`JWT_SECRET`·`DEFAULT_USER`·`DEFAULT_PASS`·`VLM_MODELS`)를 구성한 뒤 `docker compose up -d --build`로 기동한다. — 백엔드 실행 환경 미제공.
- [ ] `http://<백엔드IP>:8000/health`의 응답을 확인하고, VLM 준비가 완료될 때까지 대기한다. — 백엔드 미접속.
- [ ] RTSP 카메라(가능하면 ONVIF PTZ)를 준비하고 IP·포트·계정·경로를 확보한다. — 카메라 미제공.
- [x] Wally를 빌드하고 접속 가능한 결과물을 준비한다. — `npm run build` 성공(Vite 7.3.1, 234 modules transformed).
- [ ] A-08·A-15에서 사용할 보조 클라이언트(`client/web` 대시보드 또는 별도 브라우저의 Wally)를 준비한다. — 실제 세션 대체 검증 미수행.

## 1. 서버 인증과 로그인

- [-] A-01 서버 주소 인증 [직접] — 주소 저장과 이후 API 사용은 구현됨. 입력 단계에서 실제 서버 도달 가능 여부를 확인하지 않아 결함1로 기록.
- [x] A-02 로그인 성공과 실패 [직접] — `/api/login` 요청, 401·403 오류 표시, 5초 제한 코드 확인.
- [x] A-03 로그인 시도 제한 [직접+위임] — 429와 `Retry-After`/응답 본문 시간을 구분해 안내하도록 구현. 실제 10회 실패 호출은 30분 잠금 부작용 때문에 미수행.
- [ ] A-04 최초 로그인 강제 비밀번호 변경 유도 [직접] — 강제 변경 플래그와 진입 차단 처리가 없어 결함2로 기록.
- [x] A-05 비밀번호 변경과 전 세션 폐기 [직접+위임] — 변경 뒤 로컬 토큰을 제거하도록 구현. 기존 토큰의 서버 401 거부는 백엔드 연동 재검증 필요.
- [x] A-06 로그인 유지 세션 [직접] — 토큰 갱신과 일시 네트워크 오류 시 세션 보존 로직 확인. 실제 만료 대기는 미수행.
- [x] A-07 비유지 세션 만료 [직접] — 비유지 세션 저장·만료 처리 코드 확인. 실제 만료 대기는 미수행.
- [x] A-09 로그아웃 [직접] — 서버 주소는 유지하고 로그인 화면으로 이동하며, 주소 초기화는 별도 버튼으로 분리됨.

## 2. 스트리밍과 수명주기

- [x] A-10 카메라 프로필 등록 [직접+위임] — 저장·조회 코드 확인. 실제 `GET /camera` 응답 및 비밀번호 마스킹은 연동 검증 필요.
- [-] A-11 스트리밍 자동 시작 [직접+위임] — 카메라 로드와 재생 시작 흐름은 있음. `/state` 전환 및 router 로그 확인은 미수행(결함3).
- [ ] A-12 분석 자동 시작 [직접+위임] — 분석 시작 조건·상태 전환을 확인할 구현 근거가 부족함(결함3).
- [-] A-13 HLS 재생 [직접+위임] — HLS 재생 경로는 있음. 비인증 `index.m3u8` 요청의 401과 인증 방식은 미확정(결함4).
- [x] A-14 WebRTC 재생과 프로토콜 전환 [직접] — HLS/WebRTC 전환 코드 및 기존 Android 기기 재생 확인 기록 있음.
- [-] A-16 PTZ 제어 [직접] — PTZ 제어 UI·명령 경로는 있음. ONVIF PTZ 카메라 실기 검증 필요.
- [x] A-17 연결 회복 [직접+위임] — 오류·시간초과 뒤 장기 재시도와 온라인 복귀 재연결을 구현. streamer 로그 대조는 후속 검증.

## 3. 이벤트와 기록

- [-] A-20 클립 재생 [직접+위임] — 클립 재생은 구현됨. 문서가 요구한 재생·탐색 조작과 URL 직접 접근 거부는 미확인(결함5).

## 수정 결과

- 결함1 [앱] 로그아웃 시 서버 주소를 유지하고 로그인 화면에 `서버 주소 변경`을 분리했다 — 수정 완료. A-09 코드 검토로 확인. 주소 입력 단계의 실제 접속 확인은 미수정이며 결함1을 유지한다.
- 결함3 [앱] 스트림 오류·시간 초과 뒤 장기 재시도, 오프라인 표시, 온라인 복귀 뒤 재연결을 추가했다 — 부분 수정 완료. A-17·A-33 코드 경로 및 기존 Android/WebView 검증으로 확인. 자동 시작·외부 정지 상호작용은 미수정이다.
- 결함6 [앱] 동일 설정·이름만 변경된 경우 `/camera` 저장 요청과 스트림 재연결을 생략하고, 재생 영향 값이 바뀔 때만 재연결하도록 수정했다 — 관련 저장/재연결 문제 수정 완료. A-23 설정 비교 단위 테스트 7건과 Android WebView 검증으로 확인. 입력 형식 검증은 미수정이며 결함6을 유지한다.
- 결함3 [앱] 회전·반응형 관련 재생 안정성을 보완했다 — 수정 완료. A-35~A-42에서 PTZ 정리, 화면 상태 복원, 비율 안정화, 안전 영역, 비디오 종횡비를 기존 Android 실기기·WebView 검증으로 확인.
- 결함2 [앱] 미수정 — 강제 비밀번호 변경 API 필드와 라우터 가드 설계가 필요하다.
- 결함4 [백엔드] 미수정 — HLS 인증·서명 URL 또는 Authorization 재생 계약을 백엔드에서 확정·회신해야 한다.
- 결함5 [앱/백엔드] 미수정 — 클립 재생 UI 보완 및 비인증 URL 거부의 통합 검증이 필요하다.
- 결함7 [앱] 미수정 — 판정 표시의 수신 시각·만료·초기화 UI가 필요하다.
- 결함8 [앱/백엔드] 미수정 — 장치 제어 API 계약 확정 뒤 홈 제어와 연결해야 한다.
- 결함9 [앱/백엔드] 미수정 — 챗봇 API 계약 확정 뒤 대화 요청·응답·오류 처리를 연결해야 한다.
