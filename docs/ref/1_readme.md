# Babycat 연동 관련 문서

작성자: @claude

@skim은 ***Wally***가 ***Babycat v1.0***과 통신하기 위해 반드시 필요한 최소한의 수정을 수행하라고 지시하였고, 그 밖은 비록 문제가 존재하더라도 의도적으로 수정하지 말라고 하였다. 그 이유는 @skim이 ***Wally*** 프로젝트의 수정 권한이 없기 때문이라고 밝혔다. 따라서 여기서는 최소한으로 수정된 내용과 의도적으로 수정하지 않은, 그러나 주목해야할 배경과 계약만 기술한다.

## 1. Babycat 핵심 변경점 요약

***Babycat v1.0***은 단일 외부 진입점을 갖도록 수정되었으며, 현재 두 포트만 외부로 노출한다.

| 포트 | 용도 |
|---|---|
| 8000/tcp | Request router. 유일한 제어 진입점(HTTP API)이며 SSE·MJPEG·HLS·WebRTC 시그널링을 모두 중계한다. |
| 8189/udp | WebRTC 미디어/ICE. 저지연을 위해 router를 우회하는 유일한 경로다. |

***※ 주의: 과거의 8080(app), 8888(HLS), 8889(WHEP) 직결 포트는 더 이상 존재하지 않는다***

인증이 필요한 엔드포인트는 `Authorization: Bearer <JWT>` 헤더를 요구하며, 헤더를 설정할 수 없는 경우(SSE, 네이티브 HLS)에 한해 `?token=` 쿼리 파라미터를 허용한다. HLS는 플레이리스트와 세그먼트 요청 각각에 토큰이 있어야 한다.

비밀번호 변경(`/api/change-password`)이 성공하면 백엔드는 해당 계정의 모든 토큰을 즉시 폐기한다(FR-005). 변경을 수행한 세션도 예외가 아니므로, 클라이언트는 변경 직후 재로그인 흐름으로 이어져야 한다. 현재 앱은 변경 성공 시 즉시 로그아웃하고 로그인 화면으로 이동하며, 로그인 화면 상단에 재로그인 안내 문구를 표시한다(서버 주소는 유지되므로 서버 선택 화면을 거치지 않는다). 안내 문구의 전달은 로그아웃 사유를 sessionStorage로 넘겨 로그인 화면에서 소비하는 방식이며, 세부 설계의 조정은 앱의 몫이다.

주요 경로:

| 경로 | 비고 |
|---|---|
| `/api/login`, `/api/refresh`, `/api/logout`, `/api/change-password` | 인증 |
| `/camera` (GET/POST) | 비디오 소스 프로필 |
| `/clips`, `/clips/{name}`, `/events` | 클립·이벤트 이력 REST |
| `/state` | 시스템 상태 실시간 수신(SSE). 구성의 `/events` SSE가 이 경로로 바뀌었고, `/events`는 이력 조회 REST로 용도가 다르다. |
| `/stream` | VLM 입력 프레임(MJPEG) |
| `/prompt`, `/ptz`, `/vlm/switch` | 분석 설정·PTZ·모델 전환 |
| `/streaming/start`, `/streaming/stop`, `/analysis/start`, `/analysis/stop` | 스트리밍·분석 수명주기 |
| `/live/hls/index.m3u8`, `/live/whep` | 라이브 스트리밍 중계 |

***※ 참고: 자세한 외부 인터페이스 설계 내용은 ***Babycat v1.0***의 SDD 6장에 기술되어 있다***

## 2. 최소한의 수정 내용

### 외부 인터페이스 교정

- `src/endpoints.js` — 모든 제어 경로를 8000 단일 진입점으로 이관했다. 상태 SSE를 `/state`로 교정하고, HLS·WHEP을 router 중계 경로로 변경했다. 백엔드에 존재하지 않는 플레이스홀더(`petProfile`·`homeStatus`·`homeAlerts`·`anomalies`)와 미사용 별칭(`cameras`·`cameraStream`)을 제거했다.
- `vite.config.js` — dev proxy를 8000 기준으로 재작성하고 8888 HLS 특례를 삭제했다.
- `src/views/HomePage/CamView.vue` — hls.js 요청 전체에 Authorization 헤더를 부착했다(`xhrSetup`). 네이티브 HLS 폴백은 `?token=`을 사용하나 세그먼트 요청이 토큰을 승계하지 않으므로 hls.js 경로가 정식 경로다. WHEP 시그널링에도 토큰 헤더를 주입한다.
- `src/composables/useWebRtcStream.js` — 시그널링 요청에 헤더를 주입하는 `getHeaders` 옵션을 추가했다.

### 추가된 백엔드 계약의 최소 반영

- 최초 로그인 비밀번호 변경(`must_change_password`) — 로그인 응답의 플래그를 세션과 함께 보존하고, 로그인 후 설정 화면으로 유도하여 비밀번호 시트를 자동으로 연다. 변경 성공 시 플래그를 해제한다. (`useAuth.js`, `LoginPage.vue`, `SettingsPage.vue`, `PasswordSetting.vue`)
- 세션 대체 분류 — 백엔드는 1계정 1로그인 정책을 가지며, 새 로그인이 발생하면 기존 세션의 요청은 401(`token revoked`)을 받는다. 이 경우 리프레시 시도 없이 즉시 로그아웃하도록 `authFetch`에 분기를 추가했다. (`useFetch.js`)
- 프로필 저장 시 즉시 적용 — 등록은 스트림을 바꾸지 않으므로(FR-048) 저장한 프로필은 다음 시작까지 가저장(pending) 상태로 남는다. 저장 성공 직후 `/streaming/start`를 호출하여 새 소스로 즉시 재연결하도록 했다. 시작 엔드포인트가 재시작을 겸하므로 별도의 정지 호출은 두지 않았고(정지 순간이 생기면 자동 시작과 경쟁한다), 재시작 실패는 저장 성공과 구분하여 안내한다. (`useCamera.js`의 `saveCameraSettings`)
- 스트리밍·분석의 암묵 복원 — 구성이 가정하던 상시 동작을 조건부 자동 시작으로 복원했다. `/state` 보고에서 스트리밍이 꺼져 있으면(`streaming_active === false`, 프로필 등록 시에만) `/streaming/start`를, 스트리밍이 켜져 있고 파이프라인이 시작 대기(`pipeline_state === 'idle'`)이며 VLM이 준비(`vlm_state === 'ready'`)이면 `/analysis/start`를 호출한다. 시작 엔드포인트는 재시작을 겸하므로 비활성 상태에서만 호출하며, 실패 반복을 막기 위해 시도 간 15초 쿨다운을 둔다. (`useAutoLifecycle.js`, 홈 진입 시 활성화되어 앱 수명 동안 유지)

## 3. 수정하지 않은 것 — 프론트엔드 앱 구현자의 판단이 필요

아래 항목은 연동 계약이 아니라 앱의 동작 설계에 해당하여 손대지 않았다.

1. **스트리밍·분석의 명시적 제어.** 자동 시작(§2)은 상시 동작 가정의 복원일 뿐, 수명주기를 제어하는 화면은 여전히 없다. 유의할 상호작용이 하나 있다: 이 앱이 실행 중인 동안에는 다른 클라이언트(예: web 대시보드)가 스트리밍·분석을 정지해도 자동 시작이 이를 다시 켠다. 정지 상태를 존중할지, 명시적 제어 UI를 둘지는 앱의 설계 판단이다. 이는 다소 무책임해 보일 수 있으나, 아래와 같은 이유에 기반한다.
    - 기존 Wally는 Babycat의 SRS와 SDD같은 요구사항 분석과 설계/구현 문서가 없다 → 기준이 없으므로 완성도를 판단하기 어렵다.
    - 기존 Wally는 컴포넌트의 생명주기나 상태변화에 대한 정의가 존재하지 않고, 오로지 암묵적이고 모호한 가정으로만 구현되어 있다.
2. **이벤트 이력의 출처.** 현재 앱은 `/clips` 목록과 SSE 페이로드를 재조합하고 localStorage로 중복을 제거하여 이벤트 이력을 재구성한다. 백엔드에는 판정 문장·키워드·날짜 필터·페이지네이션을 갖춘 `/events` REST가 있으므로, 이력 화면을 이 API 기반으로 옮기면 재구성 로직 대부분을 제거할 수 있다.
3. **강제 비밀번호 변경의 강제성.** 최소 유도(설정 화면 이동, 시트 자동 열림)만 구현했다. 시트를 닫고 우회하는 것을 차단할지, 전용 화면을 둘지는 앱의 UX 설계다. 변경 전까지 백엔드는 로그인 응답마다 플래그를 다시 내려준다.
    - @skim의 요청으로, 백엔드 최초 실행 후 첫 로그인 시 비밀번호 변경 페이지로 자동으로 이동하도록 구현하였다. 
4. **세션 대체 안내.** 대체된 세션은 조용히 로그아웃된다(1계정 1로그인 규칙). "다른 기기에서 로그인되어 종료되었습니다"류의 안내 표시는 미구현이다.
5. **세션 만료 UX.** 로그인 유지(`remember_me`)를 켜지 않은 세션에는 리프레시 토큰이 발급되지 않아 액세스 토큰 만료 시 재로그인이 필요하다. 만료 임박 경고나 연장 UI는 없다.
