## 범례

- **[직접]**: 실행자가 앱 화면을 조작하고 관찰하여 수행한다.
- **[직접+위임]**: 화면 관찰(직접)에 더해, 백엔드 측 사실 확인을 AI 에이전트(Claude 등)에게 맡길 수 있는 항목이다. 위임 몫은 각 항목에 병기한다. 에이전트 없이 진행한다면 위임 몫은 실행자가 백엔드 호스트에서 직접 수행해도 된다.

### 위임 실행 안내 (에이전트 참고)

위임 몫을 수행하는 에이전트는 다음을 전제로 한다.

- 백엔드 진입점은 `http://<백엔드IP>:8000` 하나다. `POST /api/login`에 `{"username": ..., "password": ..., "remember_me": false}`를 보내 `token`을 받고, 이후 요청에 `Authorization: Bearer <token>` 헤더를 붙인다.
- 실시간 상태는 `GET /state?token=<token>`(SSE)으로 수신한다. `curl -N`으로 줄 단위 관찰이 가능하며, 판정에는 `streaming_active`·`pipeline_state`·`vlm_state`·`event_triggered`·`clip_count` 필드를 사용한다.
- 백엔드 로그는 백엔드 호스트에서 `docker compose logs -f router streamer analyzer recorder`로 관찰한다.
- 주의 1 — 세션 대체: 백엔드는 1계정 1로그인이다. 에이전트가 로그인하는 순간 실행자의 앱 세션이 대체되어 로그아웃된다. 위임 몫은 실행자와 순서를 조율해 항목 단위로 수행하고, 끝나면 실행자가 재로그인한다.
- 주의 2 — 상태 변경 금지: 상태를 바꾸는 호출(`/streaming/*`, `/analysis/*`, DELETE 계열)은 해당 시나리오가 명시적으로 요구할 때(A-15)만 수행하고, 그 외에는 관찰(GET)만 한다. 앱의 자동 시작이 동작 중이므로, 임의의 정지 호출은 다른 항목의 관찰을 오염시킨다.
- 위임 몫의 본질은 "앱 화면이 주장하는 것"을 백엔드의 사실(API 응답·로그)로 대조하는 것이다. 판정과 함께 근거(응답 본문, 로그 줄)를 결함 기록 또는 항목 옆에 남긴다.

## 실행 지침

- 실행자는 이 문서와 2_test_scenarios.md만으로 진행할 수 있어야 한다. 준비 단계에서 막히면 `1_readme.md`(연동 계약)를 먼저 확인한다.
- 순서를 지킨다. 특히 세션 대체 항목(A-08, A-15)은 보조 클라이언트 로그인이 진행 중인 세션을 끊으므로, 다른 항목 도중에 수행하지 않는다.
- 백엔드 최초 기동 직후에는 VLM 컴파일(모델당 수 분~수십 분)이 진행된다. 이 시간은 0단계에서 소화하고, 분석 관련 항목(A-12 이후)은 준비 완료 후 수행한다.
- 판단이 서지 않는 동작은 체크하지 말고 관찰 내용을 그대로 결함 기록에 남긴다(결함 여부 판정은 후속 논의로 미룬다).

발견한 결함은 아래 표에 번호를 매겨 추가한다. 증상에는 관찰된 동작과 기대 동작(시나리오의 확인 기준)의 차이를 적고, 비고에는 재현 환경(브라우저/안드로이드, 기기, 네트워크), 추정 원인, 관련 코드 위치 등 판정에 쓰인 근거를 남긴다. 심각도는 상(주 기능 불가)·중(기능 왜곡 또는 우회 필요)·경(사용성 저해) 중에서 고른다. 원인이 미확정인 결함도 등재하되 비고에 미확정임을 명시한다.

### 수정 결과

결함이 수정되면 아래에 한 줄씩 기록한다. 수정 주체([앱]/[백엔드]), 수정 요약, 검증 방법(재수행한 시나리오 식별자 또는 실측 내용)을 포함한다. 백엔드 결함은 앱 저장소에서 수정할 수 없으므로 백엔드 측에 전달하고, 전달 사실과 회신 결과를 기록한다.

- (예) 결함1 [앱] 저장 실패 시 화면이 닫히는 문제 제거 — 수정 완료. A-22 재수행으로 확인.
