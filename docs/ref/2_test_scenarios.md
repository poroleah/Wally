# Wally 실기 테스트 시나리오 (Test Scenarios)

작성 및 검토: @claude, @skim

본 문서는 Wally를 babycat 백엔드에 연동한 상태에서 수동으로 검증할 항목의 시나리오 모음이다. Wally의 원형(mewly)은 초기 아키텍처 시절에 작성되어 결함 테스트가 거의 수행되지 않았으므로, 연동 계약의 검증(A·B)과 함께 화면 흐름 전반의 기초 검증(C·D·E), 레이아웃·반응형 점검(G)을 포함한다. 실행 안내는 3_test_checklist.md를 따른다.

- 시나리오 식별자는 `A-xx`를 사용한다. babycat 측 시나리오(`M-xx`/`W-xx`)와 겹치지 않는다.
- 각 시나리오는 **절차**와 **확인** 항목으로 구성한다. 별도 전제가 필요한 경우 **전제**를 먼저 적고, 이해를 돕기 위한 구체 사례를 **예시**로 덧붙인다. 예시의 IP·키워드 등은 예에 불과하므로 실제 환경의 값으로 바꿔 읽는다.
- 연동 계약의 배경은 `1_readme.md`를 참조한다.

## 준비물

- babycat 백엔드 실기 1식(Jetson)이 필요하다. 저장소를 받아 `.env`를 구성한 뒤 `docker compose up -d --build`로 기동한다. 최초 기동 시에는 VLM 컴파일로 모델당 수 분~수십 분이 걸린다.
- RTSP(H.264) 비디오 소스 1대가 필요하다. PTZ 항목(A-16)은 ONVIF PTZ 지원 카메라를 요구하며, 그 외 항목은 대체 소스로도 수행할 수 있다.
- Wally는 저장소 루트에서 `docker compose up -d --build`(포트 5176) 또는 `npm install && npm run dev`로 실행한다.
- 초기 관리자 계정 정보(백엔드 `.env`의 `DEFAULT_USER`/`DEFAULT_PASS`)를 확보한다.
- 세션 대체·외부 정지 항목(A-08, A-15)을 위한 보조 클라이언트 1개가 필요하다. babycat 저장소의 참조 대시보드(`client/web`) 또는 별도 브라우저의 Wally를 사용한다.
- 백엔드는 1계정 1로그인 정책이다. 테스트 중 보조 클라이언트로 로그인하면 Wally 세션이 대체되어 로그아웃되므로, 각 시나리오의 절차 순서를 지킨다.

## A. 서버 인증과 로그인

**A-01 서버 주소 인증**
- 절차: 첫 화면(서버 주소 입력)에서 도달 불가능한 주소와 실제 백엔드 주소를 각각 입력해 본다.
- 확인: 유효한 주소로 진행하면 로그인 화면에 도달한다. 입력한 주소는 저장되어 이후 재방문 시 다시 묻지 않는다.
- 예시: 백엔드가 `192.168.0.50`이라면, 먼저 `192.168.0.99` 같은 빈 주소를 넣어 진행되지 않는 것을 보고, 이어서 `192.168.0.50`을 넣어 로그인 화면이 열리는 것을 본다.

**A-02 로그인 성공과 실패**
- 절차: 틀린 자격증명과 올바른 자격증명으로 각각 로그인한다.
- 확인: 실패 시 오류 문구가 표시되고 화면이 유지된다. 성공 시 홈으로 이동한다.
- 예시: `admin`에 틀린 비밀번호 `wrong1234`를 넣으면 "아이디 또는 비밀번호를 확인해주세요."가 표시되고, 올바른 비밀번호를 넣으면 홈으로 넘어간다.

**A-03 로그인 시도 제한**
- 절차: 틀린 비밀번호로 10회 연속 로그인을 시도한다.
- 확인: 10회째부터 백엔드가 429로 거부하며(잠금 30분), 앱이 로그인을 진행시키지 않고 오류를 표시한다.
- 예시: `wrong1234`로 10회 연속 시도하면, 그 뒤에는 올바른 비밀번호를 넣어도 거부된다. 30분이 지난 뒤 올바른 비밀번호로 다시 시도하면 성공한다.

**A-04 최초 로그인 강제 비밀번호 변경 유도**
- 전제: 초기 계정으로 처음 로그인하는 상태여야 한다(필요하면 백엔드 DB를 초기화한다).
- 절차: 초기 자격증명으로 로그인한다.
- 확인: 홈이 아니라 설정 화면으로 이동하고, 비밀번호 변경 시트가 자동으로 열린다. 새로고침해도 이 상태가 유지된다.
- 예시: 백엔드를 처음 설치한 직후 초기 계정으로 로그인하면, 홈 대신 설정 화면이 열리고 비밀번호 변경 시트가 이미 떠 있다. 이 상태에서 새로고침해도 다시 설정 화면과 시트로 돌아온다.

**A-05 비밀번호 변경과 전 세션 폐기**
- 절차: 비밀번호 변경 시트에서 변경을 완료한다.
- 확인: 시트가 닫히고 즉시 로그인 화면으로 이동하며(서버 주소 화면을 거치지 않는다), 입력 필드 위에 재로그인 안내 문구가 표시된다. 새 비밀번호로 로그인이 되고, 이전 비밀번호는 거부된다.
- 예시: 새 비밀번호를 저장하는 순간 로그인 화면으로 전환되고, 입력 필드 위에 "비밀번호가 변경되었습니다. 새 비밀번호로 로그인해주세요."가 보인다. 이전 비밀번호로는 로그인이 거부된다.

**A-06 로그인 유지 세션**
- 절차: `로그인 유지`를 켜고 로그인한 뒤, 액세스 토큰 만료 시간(기본 10분)이 지나고 나서 앱을 계속 조작한다. 브라우저를 닫았다 다시 열어도 본다.
- 확인: 만료 후에도 조작 시 자동으로 토큰이 갱신되어 사용이 이어진다. 재방문 시에도 로그인 상태가 유지된다.
- 예시: 로그인 유지를 켜고 로그인한 뒤 15분간 방치하고 기록 화면을 열면, 재로그인 요구 없이 목록이 조회된다. 브라우저를 닫았다 다시 열어도 로그인 상태다.

**A-07 비유지 세션 만료**
- 절차: `로그인 유지`를 끄고 로그인한 뒤, 만료 시간이 지나고 나서 앱을 조작한다.
- 확인: 로그아웃되어 재로그인이 요구된다. 브라우저 탭을 닫으면 세션이 남지 않는다.
- 예시: 로그인 유지를 끄고 로그인한 뒤 15분간 방치하고 화면을 조작하면 로그인 화면으로 돌아간다. 탭을 닫았다 새 탭으로 접속해도 로그인부터 시작한다.

**A-08 세션 대체**
- 절차: Wally 로그인 상태에서 보조 클라이언트로 같은 계정에 로그인한 뒤, Wally를 조작한다.
- 확인: Wally가 로그아웃 상태가 되어 재로그인이 요구된다. 별도 안내 문구는 표시되지 않는다(알려진 공백, `1_readme.md` §3).
- 예시: 스마트폰 브라우저의 Wally로 로그인해 둔 채 PC 브라우저에서 같은 계정으로 로그인하면, 스마트폰 쪽은 다음 조작에서 로그아웃된다.

**A-09 로그아웃**
- 절차: 설정에서 로그아웃한다.
- 확인: 초기 화면으로 돌아가고, 이전 세션 정보로 화면이 복원되지 않는다.
- 예시: 설정에서 로그아웃을 누르면 초기 화면으로 돌아가고, 브라우저 뒤로가기로는 홈에 진입할 수 없다.

## B. 라이브 스트리밍과 수명주기

Wally는 스트리밍·분석을 명시적으로 제어하지 않고, 꺼져 있으면 자동으로 켠다(조건부 자동 시작, 시도 간 15초 쿨다운). 아래 항목은 이 동작을 전제로 한다.

**A-10 카메라 프로필 등록**
- 절차: 설정의 카메라 항목에서 실제 카메라의 IP·포트·계정·경로를 등록한다.
- 확인: 저장이 성공하고, 재진입 시 저장된 값이 표시된다(비밀번호는 마스킹된다).
- 예시: IP `192.168.0.64`, 포트 `554`, 계정 `camadmin`, 경로 `stream1`을 저장한 뒤 설정을 다시 열면 같은 값이 보이고, 비밀번호 칸만 비어 있다.

**A-11 스트리밍 자동 시작**
- 전제: A-10을 완료했고, 백엔드 스트리밍은 정지 상태여야 한다.
- 절차: 홈으로 이동해 대기한다.
- 확인: 수 초~수십 초 내에 스트리밍이 자동 시작되고 카메라 화면이 연결된다. 사용자 개입(별도 시작 조작)이 필요하지 않다.
- 예시: 홈에 들어가 "카메라 연결 중" 표시를 보고 있으면, 시작 버튼을 누르지 않았는데도 잠시 뒤 실제 영상으로 바뀐다.

**A-12 분석 자동 시작**
- 전제: A-11을 완료했고, 백엔드 VLM이 준비 완료(`ready`) 상태여야 한다.
- 절차: 홈에서 대기하며 상태 표시를 관찰한다.
- 확인: 분석이 자동 시작되어 실시간 판정(장면 설명)이 흐르기 시작한다. VLM이 컴파일 중이면 준비 완료 후에 시작된다.
- 예시: 영상이 연결되고 잠시 뒤, 상태 표시에 "The dog is lying on the floor." 같은 장면 설명 문장이 주기적으로 갱신되기 시작한다.

**A-13 HLS 재생**
- 절차: 홈에서 프로토콜을 HLS로 선택하고 재생을 관찰한다.
- 확인: 영상이 재생된다(HLS 특성상 수 초의 지연은 정상이다). 인증 없이 백엔드 HLS 주소를 직접 열면 거부된다.
- 예시: 앱 안에서는 재생되지만, 브라우저 주소창에 `http://<백엔드IP>:8000/live/hls/index.m3u8`을 직접 입력하면 거부(401)된다.

**A-14 WebRTC 재생과 프로토콜 전환**
- 절차: 프로토콜을 WebRTC로 전환하고 재생을 관찰한 뒤, 다시 HLS로 되돌린다.
- 확인: WebRTC가 저지연으로 재생되고, 전환이 화면 깨짐 없이 이루어진다. WebRTC 연결 실패 시 HLS로 대체된다.
- 예시: 카메라 앞에서 손을 흔들면, WebRTC에서는 1초 안팎으로 화면에 반영되고 HLS로 되돌리면 수 초 지연으로 돌아온다.

**A-15 외부 정지와 자동 재시작의 상호작용**
- 전제: Wally가 실행 중이어야 한다.
- 절차: 보조 클라이언트에서 스트리밍(또는 분석)을 정지한다. (이 로그인으로 Wally 세션이 대체되므로, Wally를 재로그인해 홈에 둔 상태에서 관찰한다.)
- 확인: 15초 내에 Wally의 자동 시작이 스트리밍·분석을 다시 켠다. 이는 설계된 동작이다(`1_readme.md` §3 참고). 의도된 정지가 유지되어야 하는 운영 환경에서는 이 동작이 적절한지 팀 차원에서 평가한다.
- 예시: `client/web` 대시보드에서 스트리밍 정지를 누른 뒤 Wally 홈을 보고 있으면, 15초 안에 영상이 다시 살아난다.

**A-16 PTZ 제어**
- 전제: ONVIF PTZ 지원 카메라로 A-10을 완료한 상태여야 한다.
- 절차: 홈의 방향 제어로 상하좌우 이동·정지를 조작한다.
- 확인: 카메라가 이동하고, 조작을 멈추면 이동도 멈춘다.
- 예시: 방향 패드의 오른쪽을 누르고 있는 동안 카메라가 오른쪽으로 회전하고, 손을 떼면 그 자리에서 멈춘다.

**A-17 연결 회복**
- 전제: 스트리밍이 재생 중이어야 한다.
- 절차: 카메라의 전원 또는 네트워크를 잠시 끊었다가 복구한다.
- 확인: 복구 후 재생이 자동으로 회복된다(백엔드 재접속 주기에 따라 수십 초 이상 걸릴 수 있다).
- 예시: 카메라 전원을 뽑아 화면이 멈춘 것을 확인하고 10초 뒤 다시 꽂으면, 수십 초 내에 별도 조작 없이 재생이 복귀한다.

## C. 이벤트와 기록

**A-18 이벤트 감지와 실시간 반영**
- 전제: 분석이 진행 중이고, 이벤트 키워드가 카메라 앞 상황과 일치하도록 설정되어 있어야 한다(설정의 AI 감지 항목).
- 절차: 카메라 앞에서 키워드에 해당하는 상황을 연출한다.
- 확인: 감지가 앱에 실시간으로 반영된다(알림·최근 이벤트 표시).
- 예시: 키워드를 `sitting`으로 설정하고 강아지가 앉는 장면을 연출하면, 잠시 뒤 알림 목록에 이상행동 항목이 새로 나타난다.

**A-19 기록 목록과 날짜 필터**
- 전제: 이벤트 클립이 1개 이상 존재해야 한다.
- 절차: 기록 화면에서 목록을 열고 날짜를 바꿔 가며 조회한다.
- 확인: 클립 목록이 표시되고 날짜 필터가 해당 날짜의 항목만 보여준다.
- 예시: 오늘 날짜를 선택하면 방금 생성된 클립이 보이고, 클립이 없는 다른 날짜를 선택하면 목록이 비어 있다.

**A-20 클립 재생**
- 절차: 기록에서 클립 하나를 열어 재생한다.
- 확인: 클립이 재생되고 탐색(시크)이 동작한다. 인증 없이 클립 주소를 직접 열면 거부된다.
- 예시: 클립을 열어 재생 바를 중간 지점으로 끌면 그 지점부터 이어서 재생된다. 클립 주소를 복사해 시크릿 창에 붙여 넣으면 거부된다.

**A-21 감지-기록 대응**
- 절차: A-18에서 연출한 감지 직후 기록 화면을 확인한다.
- 확인: 해당 감지에 대응하는 클립이 기록에 나타난다(클립 생성까지 수십 초의 지연은 정상이다).
- 예시: 14시 20분에 감지 알림을 받았다면, 잠시 뒤 기록에서 14시 20분 전후의 클립이 확인된다.

## D. 회귀 — 참조 구현(web)에서 발견된 결함 계열

원형(mewly)이 이어받았을 수 있는 결함 유형의 재점검이다.

**A-22 카메라 설정 저장 실패 처리**
- 절차: 카메라 설정에서 잘못된 값(예: 형식이 틀린 IP)으로 저장을 시도한다.
- 확인: 실패 시 오류 문구가 표시되고 입력 화면이 유지된다(입력값이 사라지거나 화면이 닫히지 않는다). 성공 시에만 저장이 반영된다.
- 예시: IP 칸에 `abc`를 넣고 저장하면 오류 문구가 표시되며, 화면이 닫히지 않고 입력값도 그대로 남아 있다.

**A-23 설정 저장과 시청 중 스트림**
- 전제: 스트리밍이 재생 중이어야 한다.
- 절차: 카메라 설정을 변경 없이 다시 저장하거나, 카메라와 무관한 설정을 저장한다.
- 확인: 시청 중인 스트림이 불필요하게 끊기거나 재연결되지 않는지 관찰하고 기록한다.
- 예시: 영상을 보면서 설정에서 같은 값을 그대로 다시 저장했을 때, 영상이 잠깐 끊겼다 다시 붙는다면 그 사실을 기록한다.

**A-24 판정 표시의 잔존**
- 전제: 분석이 진행 중이고, 판정 표시가 흐르는 상태여야 한다.
- 절차: 카메라를 가리는 등 장면을 바꾸고 표시 변화를 관찰한다.
- 확인: 이전 장면의 판정·이벤트 표시가 부적절하게 오래 잔존하지 않는다.
- 예시: 강아지가 화면에서 사라졌는데 "The dog is sitting." 표시가 1분 이상 그대로 남아 있다면 잔존으로 기록한다.

## E. 화면 흐름 전반

백엔드 연동과 무관한 화면 기능의 기초 동작 확인이다. 세부 기대치는 앱 설계에 따르며, 여기서는 오류 없이 동작하는지와 어긋난 동작의 기록에 집중한다.

**A-25 홈 상태 표시**
- 절차: 홈의 상태 표시(온도·조명·마이크 등 부가 바 포함)를 조작해 본다.
- 확인: 각 표시·조작이 오류 없이 동작한다. 백엔드에 대응 기능이 없는 항목은 그 여부를 기록한다.
- 예시: 조명 바를 눌러 밝기 단계를 바꿔 보고, 실제로 제어되는 장치가 없다면 "표시만 바뀐다"라고 기록한다.

**A-26 캘린더와 일정**
- 절차: 일정을 추가·수정·삭제하고 화면을 재방문한다.
- 확인: 일정이 유지되고 반복·알림 설정이 저장된다.
- 예시: 내일 10시에 "병원" 일정을 추가하고 앱을 새로고침해도 일정이 남아 있으며, 삭제하면 목록에서 사라진다.

**A-27 알람 설정**
- 절차: 알람 항목을 켜고 끄며 저장한다.
- 확인: 설정이 유지된다.
- 예시: 알람 하나를 끄고 설정 화면을 나갔다 다시 들어와도 꺼진 상태가 유지된다.

**A-28 챗봇**
- 절차: 챗봇 화면에서 메시지를 주고받아 본다.
- 확인: 오류 없이 동작하는지, 어떤 백엔드에 의존하는지 관찰하고 기록한다.
- 예시: "안녕"을 보내 응답이 오는지 보고, 응답이 없거나 오류가 난다면 어떤 의존성(외부 서비스 등) 때문인지 관찰한 대로 기록한다.

**A-29 프로필과 테마**
- 절차: 프로필(이름·이미지)을 수정하고, 다크 모드를 전환한다.
- 확인: 프로필이 유지되고, 테마가 전 화면에 일관되게 적용된다.
- 예시: 프로필 이름을 "콩이"로 바꾸고 새로고침해도 유지되며, 다크 모드를 켜면 홈·기록·설정 화면이 모두 어두운 테마로 표시된다.

## F. 안드로이드 실기 (Capacitor)

본문(A~E)은 브라우저 기준이다. 아래는 APK로 빌드·설치한 실기에서만 확인할 수 있는 항목이다. 빌드는 Capacitor 표준 절차(`npx cap sync android` 후 Android Studio/Gradle)를 따른다.

**A-30 APK 빌드와 설치**
- 절차: 안드로이드 프로젝트를 빌드해 실기에 설치하고 실행한다.
- 확인: 앱이 기동하고 서버 주소 입력 화면이 표시된다.
- 예시: Android Studio에서 실기를 연결해 Run으로 설치하면, 첫 실행에서 서버 주소 입력 화면이 뜬다.

**A-31 핵심 흐름 재확인**
- 절차: 실기에서 A-01·A-02·A-11·A-13·A-14를 재수행한다.
- 확인: 브라우저와 동일하게 동작한다. WebRTC(UDP 8189)가 이동통신망·공유기 환경에서도 연결되는지 함께 기록한다.
- 예시: 백엔드와 같은 Wi-Fi에 물린 스마트폰에서 로그인과 HLS·WebRTC 재생까지 브라우저와 같은 결과가 나오는지 확인하고, WebRTC만 실패한다면 그 네트워크 구성을 기록한다.

**A-32 백그라운드 복귀**
- 전제: 스트리밍이 재생 중이어야 한다.
- 절차: 홈 버튼으로 앱을 백그라운드로 보냈다가 잠시 후 복귀한다. 화면 잠금 후 해제도 수행한다.
- 확인: 복귀 시 스트림이 재생 상태로 회복된다(자동 재연결 포함).
- 예시: 재생 중 홈 버튼을 눌러 30초 뒤 앱으로 돌아오면 영상이 다시 재생된다. 화면을 잠갔다 해제한 경우에도 같다.

**A-33 네트워크 전환**
- 전제: 스트리밍이 재생 중이어야 한다.
- 절차: Wi-Fi에서 이동통신망으로(또는 반대로) 전환한다.
- 확인: 전환 후 세션과 재생이 회복된다. 백엔드가 사설망에만 있는 경우 이동통신망에서는 도달할 수 없는 것이 정상이며, 그 경우에는 오류 표시를 확인한다.
- 예시: 재생 중 Wi-Fi를 끄면, 백엔드가 외부에서 도달 가능한 경우에는 재생이 회복되고, 사설망 전용인 경우에는 연결 오류가 표시된다.

**A-34 네이티브 알림**
- 전제: 이벤트 감지가 가능한 상태(A-18의 조건)이고, 앱에 알림 권한이 부여되어 있어야 한다.
- 절차: 앱을 백그라운드에 두고 감지를 연출한다.
- 확인: 안드로이드 알림이 도착한다. 동작 세부는 `ANDROID_NOTIFICATION_SYSTEM.md`를 따른다.
- 예시: 앱을 백그라운드에 두고 A-18과 같은 장면을 연출하면, 안드로이드 상태 바에 감지 알림이 도착한다.

**A-35 화면 회전과 전체화면**
- 전제: 스트리밍이 재생 중이어야 한다.
- 절차: 기기를 회전하고, 전체화면 재생을 전환한다.
- 확인: 레이아웃이 깨지지 않고 재생이 유지된다.
- 예시: 기기를 가로로 돌리면 영상이 화면에 맞게 확장되고, 세로로 되돌리면 원래 배치로 돌아오며 그동안 재생이 끊기지 않는다.

## G. 레이아웃과 반응형

원형은 스마트폰 세로 화면을 기준으로 설계되었고, 화면 방향을 기기 센서가 아니라 뷰포트의 가로/세로 비율(가로가 세로보다 큰지)로 판정한다. 이 판정은 창 크기 조절·화면 키보드·주소창 표시 같은 비율 변화에도 반응하므로, 회전이 아닌 원인으로 배치가 전환되거나 전환 후 상태가 대칭적으로 복원되지 않는 문제가 생길 수 있다. 아래 항목은 이 계열과 일반적인 반응형 문제를 점검한다. 브라우저 기준으로 작성하되, 안드로이드 실기에서도 병행 확인하면 좋다(A-41은 실기가 필요하다).

**A-36 창 비율 변화에 따른 화면 전환의 대칭성**
- 전제: 스트리밍이 재생 중이어야 한다.
- 절차: 데스크톱 브라우저에서 홈을 띄우고, 창 너비를 천천히 늘려 가로가 세로보다 커지게 했다가 다시 줄인다. 이를 수차례 반복한다.
- 확인: 비율이 가로형이 되면 가로 배치로 전환되고, 세로형으로 되돌리면 원래의 홈 배치로 복원된다. 전환이 한 방향으로만 동작하거나, 되돌렸을 때 다른 상태(확장 보기 등)에 머무르면 결함으로 기록한다.
- 예시: 창을 넓히면 자동으로 전체 화면형 가로 배치가 되는데, 창을 도로 좁혔을 때 원래 홈 화면으로 돌아오지 않고 확장 보기 상태로 남는다면 그 상태 전이를 그대로 기록한다.

**A-37 회전 반복과 상태 복원**
- 전제: 스트리밍이 재생 중이고, 모바일 기기 또는 브라우저 개발자 도구의 기기 모드를 사용할 수 있어야 한다.
- 절차: 세로→가로→세로 회전을 여러 차례 반복한다. PTZ 패드나 부가 바(드로어)를 연 상태에서도 반복한다.
- 확인: 회전할 때마다 배치가 일관되게 전환되고, 열려 있던 패드·드로어가 잘못된 위치에 잔존하지 않으며, 재생이 유지된다.
- 예시: 가로에서 PTZ 패드를 연 채 세로로 돌리면 패드가 닫히는 것이 정상인데, 다시 가로로 돌렸을 때 화면 요소가 겹쳐 남아 있다면 기록한다.

**A-38 경계 비율에서의 안정성**
- 전제: 스트리밍이 재생 중이어야 한다.
- 절차: 창의 가로·세로 길이가 거의 같아지는 지점 근처에서 너비를 미세하게 반복 조절한다.
- 확인: 배치가 빠르게 진동(플리커)하지 않고, 전환할 때마다 영상이 길게 끊기거나 재연결을 반복하지 않는다. (배치 전환 시 인라인 영상을 다시 붙이는 구조이므로, 경계에서의 반복 전환은 재생 끊김을 누적시킬 수 있다.)
- 예시: 정사각형에 가까운 크기에서 몇 픽셀씩 드래그할 때 화면이 가로/세로 배치를 오가며 깜빡이고 영상이 매번 다시 연결된다면 기록한다.

**A-39 화면 키보드와 주소창에 의한 뷰포트 변화**
- 전제: 모바일 브라우저 또는 실기에서 로그인 상태여야 한다.
- 절차: 입력 필드(채팅, 설정의 입력 칸 등)에 포커스를 주어 화면 키보드를 띄웠다 내리고, 페이지 스크롤로 브라우저 주소창이 나타났다 사라지게 한다.
- 확인: 키보드·주소창에 의한 화면 높이 변화가 가로 모드로 오인 전환되거나 입력 중인 요소를 가리지 않는다.
- 예시: 키보드가 올라와 화면 높이가 절반이 되어 가로가 세로보다 커졌을 때, 배치가 갑자기 가로 모드로 바뀐다면 기록한다.

**A-40 좁은 화면과 긴 텍스트**
- 절차: 좁은 화면(폭 360px 수준)에서 각 화면을 훑고, 긴 텍스트(긴 장면 설명 문장, 긴 일정 제목, 긴 프로필 이름)를 만들어 표시를 관찰한다.
- 확인: 가로 스크롤이 생기지 않고, 긴 텍스트는 줄바꿈 또는 말줄임으로 처리되며, 버튼·아이콘이 겹치지 않는다.
- 예시: 일정 제목을 40자 이상으로 저장했을 때 캘린더 칸을 넘어 나오거나, 홈의 장면 설명 문장이 표시 영역을 넘친다면 기록한다.

**A-41 세이프 에어리어와 시스템 UI**
- 전제: 노치 또는 제스처 바가 있는 안드로이드 실기여야 한다.
- 절차: 홈(세로·가로)과 주요 화면에서 화면 가장자리의 컨트롤을 관찰한다.
- 확인: 노치·상태 바·제스처 바가 앱의 버튼·내비게이션과 겹치지 않는다. 안전 영역 여백 처리가 일부 화면에만 적용되어 있으므로, 겹침이 발견되면 어느 화면인지 구체적으로 기록한다.
- 예시: 가로 모드에서 좌측 컨트롤이 노치에 가려지거나, 하단 내비게이션이 제스처 바와 겹쳐 눌리지 않는다면 기록한다.

**A-42 비디오 종횡비 대응**
- 전제: 종횡비가 다른 소스(16:9와 4:3 등)를 준비할 수 있으면 둘 다 확인하고, 없으면 한 소스로 전환·회전 후의 비율 유지만 확인한다.
- 절차: 소스를 재생하고 확장 보기·가로 전환을 오간다. 종횡비가 다른 소스가 있으면 바꿔 가며 반복한다.
- 확인: 영상이 찌그러지지 않고(비율 유지), 잘림·여백 처리가 일관되며, 전환 후에도 비율이 유지된다.
- 예시: 4:3 카메라 영상이 16:9 틀에 맞춰 늘어나 보이거나, 가로 전환 후 세로로 복귀했을 때 비율이 깨져 있다면 기록한다.
